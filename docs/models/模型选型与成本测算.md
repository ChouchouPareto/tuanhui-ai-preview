## 1. 选的不是一个万能模型

R8 当前选择：按用户要求统一先用千问。受控父任务/可选文案使用 `bailian_text_model`（默认 qwen-plus），识别保留既有 Qwen VL/OCR 配置，生图使用现有 qwen-image-3.0。本轮真实3次语言+1次图片，未比较其他模型；两次父模型过度澄清反映PE分支混用，不能据此断言模型整体能力不足或选型胜出。具体耗时、授权与失败记录见[实测报告](../technical/千问受控编排与功能工作台_2026-09-21.md)。

| 任务 | 必需能力 | 先看什么 | 不应承担 |
| --- | --- | --- | --- |
| 意图和动作提案 | 中文上下文、否定/修改意图、结构化输出 | 误生图率、对象定位、澄清质量 | 绕过授权执行工具 |
| 门头/菜单识别 | 图像文字与区域、候选与证据定位 | 店名/数值准确、误分类 | 将不确定识别写成事实 |
| 创意与文案 | 行业语境、事实约束、区域字数 | 吸引力、事实正确、可排版 | 代替固定价格和权益数据 |
| 图片生成/编辑 | 主体、风格、构图遵循、参考控制 | 母版质量、无字遵循、保真 | 保证文字最终准确 |
| 质检 | 程序几何检查，必要时视觉理解 | 漏检、误杀、耗时 | 一个自评分宣称作品合格 |

查询进度、权限校验、裁切、确定性改字、幂等和费用统计不需要额外 LLM。先避免无必要调用，再比较单次模型价格。

## 2. 当前配置证据与待核验项

静态代码基线 64deee5 的配置默认值包括 `qwen3-vl-plus`、`qwen-vl-ocr-2025-11-20`、`qwen-image-3.0`、`doubao-seedream-5-0-260128`；示例配置与运行环境可能不同。它们仅为现有接入线索，不是对当前公开可用性、能力和价格的声明。不要把 `.env` 密钥复制到选型报告。

每次真实测评前从服务商官方资料确认：完整 model_id/版本、地域、接口、输入图片限制、输出比例、结构化能力、异步查询/取消能力、用量字段、缓存规则和计费单位，并在当次报告附实际页面 URL、访问日期与配置脱敏快照。未确认的候选不进入付费测试。

## 3. 候选分组与选择规则

- A：当前实际运行的理解模型，作为基线，需从请求日志确认。
- B：同供应商低延迟/低成本候选，验证简单路由能否替代，而非按“Flash”等名称直接判定。
- C：更强推理/多模态候选，验证复杂纠正、对象歧义和识别收益。
- D：当前图片模型与另一已接入图片候选，用相同输入和 PE 单独比较；不要将理解模型分数与生图分数合并冒充总能力。

先过安全门槛，再比可执行正确率与质量，最后在合格候选中比较成本和时延。若只有复杂任务受益，可按任务难度升级；升级必须可观测且受授权控制，不默认失败后连续换模型。

## 4. 实验步骤

1. 固定需求集、数据版本、PE、工具 schema、图片规格、推理参数、区域和重试策略；记录模型可配置项差异。
2. 用 [评测方案](../evaluation/评测与验收方案.md) 的种子集调通，随后增加未参与调参的真实匿名案例；种子集不作为泛化证明。
3. 同一案例在候选间配对比较；图像随机性通过预先设定重复次数观察，不能只保留最好的一次。
4. 单独记录首响应、总时延、输入/输出/缓存/图片用量、失败与未知结果；供应商失败也是样本。
5. 文案和视觉匿名打分；评审不知道供应商，先独立评分再讨论分歧。固定同一展示尺度和裁片检查方式。
6. 输出差异、失败簇、成本区间、推荐范围及不适用任务。发现副作用违规即停止相关路线，不以高平均分抵消。

## 5. Token 与成本公式

每个真实请求保存供应商原始 usage 的允许字段及归一化版本。若 total input 包含 cached input，未缓存输入 = input_total − cached_input；若供应商定义不同，按其说明转换，不能重复加一遍缓存。

文字请求费用 = 未缓存输入量 × 输入单价 + 缓存输入量 × 缓存单价 + 输出量 × 输出单价（统一每百万或每千单位）。推理 Token 是否包含在输出费用中，按服务商口径确认，不自行再加一次。

图片请求可能按张、分辨率档位或 Token 计费。选择其实际计费模型；同一次图片请求不能同时套用“按张价”和已包含图片的 Token 费用。失败收费、批量、折扣、税费、币种分别记录。

任务成本 = 所有关联实际请求费用 + 可归属的本地/存储/传输成本。还应区分：估算、供应商用量推算、账单核对。缺少 usage/单价的请求计入“金额未知”数量，不当作免费。

月度情景测算 = 各任务类型月量 × 实测平均任务成本 + 固定基础设施费用；另列失败、用户修改和高峰容量情景。月量、修改率与订阅价格需要业务输入，现在不填虚构数字。

多 Agent 成本按调用图求和，延迟按关键路径计算：并行分支耗时近似取最大值，加协调和串行段，不能直接把全部 Token 相加当耗时。父 Agent 不仅有子任务成本，还有计划、上下文汇总和问题处理成本；若分支结果不可复用会进一步增加。

## 6. 提效优先级

1. 进度/查询/纯文字本地修改不触发生图。
2. 保留底图和结构化事实，少传全量对话；按素材哈希复用识别结果。
3. PE 只注入当前类目、用途、模板，不把整库或稿定原图每轮发送。
4. 对独立只读步骤做并行，保留取消、预算及并发限流。
5. 再比较模型和参数；每项优化以同条件端到端耗时与质量对照验证。
