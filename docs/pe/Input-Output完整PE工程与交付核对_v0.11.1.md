# Input → Output 完整 PE 工程与交付核对 v0.11.1

日期：2026-09-13。状态：代码与离线回归已实现；真实模型的视觉质量、耗时和费用仍须单独验收。

本文是 v0.10.1 之后的增量整合审核版，不覆盖此前文档。运行时以文中对应源码为准；源码快照通过 `scripts/backup_pe.py` 独占创建、带时间戳及 SHA256，位于 `docs/pe/backups/`。

## 1. 本次边界

按原问题顺序收尾：输入交互 → 素材与项目恢复 → 生成/导出 → PE、类目和排字 → 续聊 → 计时与调用记录 → 输出类型与批量执行。

不在本次开发范围：产品父子 Agent 编排、构图模板库的新建/扩充及 Figma 重建、无限画布、商家经营后台。此前已有模板及审核文件保留，不代表本次重新建设或已经通过你审核。

实际架构是：一个需求理解模型调用 + 程序化规划/校验 + 图片模型 + 本地排字/检测/导出。`creative_workflow.py` 中的角色契约是数据分工说明，不是运行中的多 Agent。

## 2. 用户从输入到结果的步骤

1. 进入一键生图，写一句想法或上传照片。首页保留「创作 / 一键生图 / 全案设计」入口。没有自动填入的真实品牌名，也没有必须填写的文字表格模板。
2. 用户点击「开始生成」。首次需要清楚知晓调用及素材使用的授权；这不是要求用户再填写店名、菜品。
3. 系统合并本轮话语、已有事实和素材角色，理解需求。已提供内容不再重复问。仅在缺少可执行方向、事实冲突或用户明确要求实拍但没有可用实拍时，给出短句解释/下一步。
4. 单项输出按已授权范围继续生成；全案或多张详情页先列出交付项和最多图片调用数，再由用户批准该批范围。服务端复核数量，不能由前端绕过。
5. 展示实际阶段、已用时间；有同类历史样本才显示耗时区间。刷新、离开后回来都读同一任务，不重新付费提交。
6. 作品图片点击预览，下载为独立动作。可切换带水印/无水印导出。批量作品分项展示，中断时保留已完成部分。
7. 用户直接接着说哪里想改。程序建立有父版本关联的新修订，旧作品不覆盖。明确的纯标题修改可复用原底图本地重排；改风格/内容/素材则走新图调用。

### 用户不必懂提示词工程

自然输入例如：「给我的面馆做团购五连图，暖一点」「用这张照片做套餐主图」「只把标题改成：下班来吃面」。系统不要求用户按槽位填空。

供运营测试使用、不会自动塞进输入框的标准描述：

> 为【店名/品类】制作【图片用途】；想突出【产品/套餐/特色/情绪场景之一】；偏好【风格，可省略】；需要出现的真实文字为【可省略】；价格及活动条件为【有依据才填写】；参考素材【可省略】。

这不是必填清单。无店名可以不展示店名，无价格就不展示价格，无照片可选择 AI 示意；不能为补齐模板而虚构销量、口味、折扣或商家资质。

## 3. 输出合同（本轮确认后的标准）

| 类型 | 生成/排版画布 | 导出 | 核心内容区域 |
| --- | --- | --- | --- |
| 五连图 | 一张 20:3 母版，最终 4000×600 | 最后裁成 5 张 800×600 | 模板规定区域；不先生成五张拼接 |
| 三连图 | 一张 12:3 母版，最终 2400×600 | 最后裁成 3 张 800×600 | 同上 |
| 首页装修图 | 单张 4:3，800×600 | 1 张 | 普通安全边距 |
| Logo 图 | 4:3，800×600 | 1 张 | 中央 1:1；核心内容 x=0.125～0.875 |
| 套餐主图 | 4:3，800×600 | 1 张 | 同 Logo |
| 代金券主图 | 4:3，800×600 | 1 张 | 同 Logo |
| 菜品单品图 | 4:3，800×600 | 1 张 | 已合并原「推荐菜」 |
| 详情页 | 每张都是 4:3，800×600 | 1～9 张；用于链接内部 | 不把它默认为长图裁切 |
| 团购宣传图 | 4:3，800×600 | 1 张 | 普通安全边距 |

全案不是第十种尺寸：默认交付代金券主图 + 五连图 + Logo，可在设置中选择其他类型。默认最多 3 次图片模型调用，五连图本身算 1 次，不是 5 次。多张详情页可在对话里说「做3张详情页」；当前数量上限 9，超过范围需要分批。

1:1 限制作用于核心 Logo、主体、文案与价格；装饰性纹理、线条、插画背景可延伸。当前程序严格限制本地文字和贴入实拍的区域，模型生成的主体位置仍是提示词约束，不能宣称像素级完全服从。

Qwen 请求：五图 2000×300、三图 1200×300、单图 1024×768，再按最终画布排版导出。其他供应商未等价验证，不承诺其原生支持同样宽高比。

对应：`output_contract.py`、`layout_catalog.py`、`design_plan.py`、`image_generation.py`、`frontend/lib/output-options.ts`。

## 4. Input → Output 的程序合同

| 阶段 | 输入 → 输出 | 约束与失败处理 |
| --- | --- | --- |
| 输入保存 | 用户本轮文字、已有事实、素材清单 → IntakeRevision | request_key 幂等；事实来源保留；用户最新明确修正优先 |
| 理解 | 精简事实上下文 + 本轮文字 → 事实候选、creative_draft、style_hint | 一个文字理解调用；证据引用校验；AI 回复不能当作用户事实回填 |
| 类目路由 | 用户内容/已知事实 → 一级、二级类目 PE | 不确定归 general；推断仅设计提示，不等于经营事实 |
| 输出规划 | 类型 + 文案 + 素材 → DesignPlan | 固定比例；选择已有兼容布局；程序验证区域、边界、容量 |
| 授权入队 | 快照/hash + 调用数量 → Confirmation + Task | 同修订重复确认复用同任务；worker 不在线不锁定为已生成 |
| 无字底图 | 视觉 PE + 允许的资料 → 图片模型返回 | 模型不画正文；默认不追加供应商提示词扩写/思考；不自动切换付费模型 |
| 本地质检 | 返回字节 → 原图、OCR 记录 | 原始返回先保存；发现底图文字拦截，避免再次叠字；失败不重新生图 |
| 排字 | 母版 + 确定文案 + 坐标区 → 成品母版 | 字宽/真实字形边界计算；换行缩字号；最低字号仍放不下则报错，不截断关键文字 |
| 导出 | 母版 → 长图/切片/无水印版 | 五/三图此时才切；单图不重复显示同一切片；保留原任务 |
| 追问 | 父版本 + 新指令 → 新版本或本地文字修订 | 纯文字操作不调用图片模型；范围变化重新规划；不覆盖历史作品 |

长画布切片是上传规格，不是五个必须填满文字的独立广告位。允许视觉跨片连续，但文字区域须处于合法安全区，避免裁到半个字。

## 5. PE 的分类与装配

不是把所有规则拼成一段超长提示词。装配顺序为：全局事实边界 → 输出类型合同 → 一级/二级类目 → 本次创意文案 → 已选布局坐标 → 风格 → 本地导出规则。

一级：餐饮、丽人、休闲娱乐、购物、未知。当前二级入口：

- 餐饮：地方特色菜、火锅、烧烤、酒吧、轻餐、面食、饺子馄饨、咖啡茶饮。
- 丽人：美发、美甲、美容护理。
- 休闲娱乐：桌游娱乐、运动、休闲养生。
- 购物：零售、鲜花、服饰。

当前是初始规则包，不代表各二级类目都有经过实图验收的专属设计模板。后续案例拆解应独立绑定类目、输出类型、布局版本、风格和审核状态，不绑死在「餐饮五图」一条路径。

运行 PE 文件：

- `services/prompts/copywriting_v2.md`：吸引力、场景动作、真实事实、敏感宣传限制；主标题最多 24 字、副标题最多 36 字，重复文案去重。
- `services/prompts/generation_v3.md`：完整母版视觉、无字、区域留白、门头不得复现。
- `services/category_policy.py`：类目词表、创作方向和安全降级文案。
- `services/creative_workflow.py`：创意草案校验、纯标题修改、布局选择上下文。
- `services/layout_catalog.py` / `output_contract.py`：已有布局坐标和单图安全区适配，不是原参考图。

如模型创意不合格，使用可解释的保守降级文案，不编活动。合规词检查只是一层产品防线，不能称为完整法律审查；有吸引力仍需人工样本评审。

## 6. 文案、排字与素材边界

### 排字主路径

默认「AI 出无字视觉 + 程序统一排字」。先规划文字区，再生成底图，最后按已规划区域排字，并非做完图再随便盖字。正文/价格不同时交给模型和程序绘制。

优点：内容准确、避免双重文字、可保留底图只改字、费用较低。局限：当前字体与艺术字变化有限；复杂曲线字、字形与食物穿插等美术效果不能视为已实现。模型一体化艺术字路径尚未成为可选生产模式。

### 素材

只有 `asset_type=product` 且 `semantic_role=dish/signature_dish` 可进入实拍成品；storefront/menu 不得成为入画素材。门头/环境可以提供已核对的文字、配色和风格资料，不能把门头照片贴入成品。

重要边界：当前分类基于上传角色/识别与用户校正。若用户把门头误标成菜品，不能保证程序仅凭标签识别这个错误。自动语义识别的正确率、陌生品牌名称与环境色彩提取，需要真实素材专项验收；不能承诺零误识别。资料冲突不能静默覆盖正确店名。

参考案例图片首先供你审核，运行时使用结构化坐标/区域职责，不把稿定原图反复附带给图片模型。这样减少视觉输入与照搬风险。案例拆解及 Figma 可编辑重建本次暂缓。

## 7. 续聊、计时、Token 与费用

续聊：旧「同一修订只允许一次理解」的调用防重规则保留，但新用户输入建立新修订/续作，不再让用户寻找已经不存在的智能理解开关。网络重连只 GET；新创作/修订才 POST。

纯文字修改目前是明确、可识别的标题修改主路径，例如「只把标题改成：……」。如果同时改照片、类型或风格，就不是免费重排；整套全案的逐项局部编辑尚未做成独立编辑器。

时间埋点：understanding、queue、generation、image_model、layout_export 的开始、结束、失败/取消，以及项目/创作/任务关联。界面按服务端时间显示已用时间；最近 14 天最多 100 个同阶段/模型工作负载成功样本，至少 5 个才给 P50～P90 区间。冷启动显示样本不足，不编造预计 30 秒，也不靠假进度条宣称模型进度。

计量：保存 ModelCallRecord、ModelUsageRecord，记录供应商/模型/状态、实际 usage、请求耗时、下载耗时、提示词字符数与哈希。`GET /api/v1/projects/{id}/usage` 可查看安全摘要；未返回 Token 时为 null，不伪造 0；图片数量不等同文字 Token。此接口不暴露提示词正文、密钥或原素材。

优化：复用结构化事实、仅提交当前消息，避免整段历史反复传入；一个理解调用同时产出创意草案；明确标题修改跳过理解及生图；关闭默认的供应商二次扩写；OCR 编译缓存。以上减少不必要步骤，但没有真实压测数据前不承诺耗时降低百分比。

停止不能撤销已到供应商的请求费用。结果未知不自动重试；本地排字失败不触发第二个供应商。批量执行每项独立保存，任一失败停止后续；已成功、已失败任务再次进入执行函数不会重复调用。

## 8. 原问题所在环节与预防

| 原问题 | 对应流程问题 | 本轮防线 |
| --- | --- | --- |
| 连图只有背景/极少有效内容 | 视觉任务被收窄成装饰纹理、固定覆盖排版影响结果 | 整张母版视觉职责、类目主体、区域化排版；旧模式不用于新 region-master-v3 计划 |
| 标题严重重叠 | 模型先画字，程序再写同一内容；文字容量没有严格保证 | 无字 PE + OCR 拦截 + 字形边界/容量校验 + 精确去重 |
| 再次输入弹“本修订已理解” | 调用去重与用户新一轮输入混用 | 修订/续作隔离，既防重复计费又允许新需求 |
| 回来打不开项目、查看不到结果 | 路由恢复/任务状态与界面草稿混合 | 读取持久化项目/创作/任务；短暂网络失败恢复查询，不重提生成 |
| 图片点击直接下载 | 预览与下载使用同一交互 | 图片打开预览，独立下载按钮 |
| 看不懂等待多久 | 缺少阶段时间与历史样本 | 持久化 hooks、已用时间、真实历史区间 |
| 五/三/单图规格串用 | 输出类型没有贯穿请求、规划和导出 | 共用类型合同，贯通 intake → plan → task → gallery 的回归测试 |
| 需要多项时隐藏增加调用 | 一个确认只约束单张，没有批量数量预算 | 列表、数量授权、服务端上限、逐项执行与失败停止 |

旧作品不自动重生成或改写。文案吸引力、真实图像构图服从和模型稳定性仍须用固定案例集人工验收；单元测试通过不是视觉质量合格。
