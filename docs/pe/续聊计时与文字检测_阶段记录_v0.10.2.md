# 续聊、计时与文字检测：阶段记录 v0.10.2

日期：2026-09-12。状态：阶段实现，不代表 v0.11 全部需求已完成。保留 v0.10.0、v0.10.1 原文，不覆盖历史 PE 快照。

## 已核实的原因

1. 失败后续聊：理解任务原来按 creation + revision 标识；理解超时不会增加 revision，修改后的输入仍撞上旧任务，被 AI_REVISION_ALREADY_USED 拦截。页面提示关闭一个已经不存在的开关。
2. 跨作品续聊：新建 creation 时不继承上一版摘要，已知事实与对话容易丢失。
3. 耗时：理解失败可能记录为 0；生图记录将模型请求、图片下载和本地排版混为一个时间；页面没有权威服务端阶段时间。
4. 双重文字：已查看任务 696b9645-75cb-442a-a339-17089a56aa25 的 model-visual.png。原图已经有「山西面馆」「今天」「来一碗面」，本地文字层再次排字，导致重叠。只写“不要文字”的 PE 不能代替输出检查。

## 本阶段落地

- 理解请求身份改为 creation + revision + request_hash。相同失败请求不自动再次调用；修改后的新请求可继续，同一 creation 的并发请求用数据库锁串行化。
- 对异常中断超过保守期限（至少 10 分钟）的理解任务释放遗留锁，记录结果未知；不自动重新发送。这个期限是异常回收上限，不是用户预计等待时间。
- 已确认作品下继续对话创建子 creation，继承摘要，保留 parent_creation_id。原作品不覆盖，前端可以展开上一版；刷新后通过 previous_task_id 恢复上一版入口。
- WorkflowEvent 存储理解、排队、生成全流程、模型请求及下载、排版与导出各阶段事件。记录任务、模型、开始、结束、耗时和错误；不额外存储用户图片、原文或密钥。
- 前端 useWorkflowTiming 根据服务端开始时间显示秒数，不依赖页面加载时刻；轮询只读，不触发生图。
- 预计耗时采用近期 14 天最多 100 条成功样本的 P50–P90；至少 5 条样本才显示区间。全流程按实际模型、渲染模式、输出类型和模板版本分组。冷启动明确显示样本不足，不画虚假倒计时。
- 底图 PE 不再携带需要印出的完整商家名、价格和 copy 文案，只携带构图、视觉主题、风格、文字颜色与品牌色。
- 当前程序排字路径新增本地 OCR 防重复落字检查。发现底图带字时保留原始模型图和 text-guard.json，停止排字及成功交付；不自动付费重试。
- 本地 OCR 使用 macOS Vision，Swift 程序按源码哈希编译缓存，调用不收费。缺少本地检查器时在生图前失败，不先扣费再发现缺依赖。跨平台部署仍需接入对应 OCR 实现。
- 模型请求成功但排版失败，模型调用记录仍记为成功；流程失败另记。模型请求耗时目前包含图片下载，不伪称纯推理时间。

## 排字边界

本阶段未将整个产品强制切换成单一排字路线，也未新增“AI 全文排字”路由。当前程序排字路径的防重叠检查先补齐。

OCR 有漏检和误检风险，尤其是艺术字；通过检查不等于文案合规或视觉质量百分百合格。当前拦截是避免错误成品交付，不是自动修复图中文字。模型输出不合格不自动再次收费。

每个案例记录：来源文件 → 一级/二级类目 → 输出类型 → 主辅视觉 → 文案职责与字数容量 → 字体与色彩层级 → 素材数量 → 裁切检查 → 原创模板 ID/版本 → 审核状态。

构图、风格、创意文案分开建库再组合。案例中的环境、门头、菜品、店名、价格、宣传承诺不自动变成用户的事实。缺少真实菜品不得为了填模板而虚构实拍。
