修订：R7，2026-09-21。依据：主 PRD 与用户确认；焚诀 `agent-blueprint/BLUEPRINT.md`、`AI产品Vibe Coding通用技术栈手册.md`。这是后端实施文件，不是整体完成报告。

## 产品与阶段

R8 更新：用户允许先提供简洁功能工作台，正式 Figma/贴图后审，覆盖下述“尚不接前端”的旧阶段限制。新增受控 Agent 队列、模板指纹审核、工作区版本接口及临时前端，详见[功能工作台合同](../technical/千问受控编排与功能工作台_2026-09-21.md)。保持单用户本地边界，未上线公网；正式模板发布门禁、复杂语义与无限画布还未完成。

多轮对话驱动的营销图片创作产品，一键、专业、全案共享业务后端。用户已将父子 Agent、正式模板库、可编辑画布及全案独立端口正式纳入范围，取代此前暂缓状态。执行顺序：后端能力开发与验收 → Figma 页面审核 → 正式前端接入 → 独立部署验收。

本阶段后端可验证文字/图层结构、修改、版本、模板和编排；拖动体验、视觉布局及可用性不凭 API 测试宣称通过。现有页面维持，不并行创建一套新正式前端。

## 采用与偏离

- 保留现有 Python 3.12.14、FastAPI、Pydantic、SQLAlchemy、pytest；不为手册默认 3.11 无理由迁移。
- 保留 SQLite、本地生成文件和现有 worker/API；新增对象数据按版本存储，数据库迁移增量可复核。当前本地单用户边界不冒充多租户生产隔离。
- 付费模型沿用现有后端网关与配置，不导入焚诀目录的密钥，不无理由新增供应商。模型能力按实际契约评测，不把“接通”写为“选型胜出”。
- 固定输出/版本/文件/权限检查采用确定性程序；父 Agent 做有限的意图和任务提案，子 Agent 独立上下文、按需调用。禁止模型提交代码或递归创建无限子 Agent。
- 图层先存结构化 JSON 与稳定 ID；引用后端登记素材，不接收任意文件路径或外网 URL。图片保存在受控文件目录，数据库存引用与指纹。
- 慢模型动作使用持久化任务；本地短操作同步返回，导出有可查询结果。API 失败不得转成付费回退。
- R6专业入口已落地独立持久队列，与一键队列共用worker调度；素材入队指纹和执行前复核、原子领取、过期租约待核对、终态保留已离线测试。旧未入队任务不自动重放，混合新旧进程须在切换前处理。未新增外部队列服务。
- 不引入未触发需求的 RAG/向量库、定时自治、微服务或新云平台。

## 七层落地与贯穿流程

| 层 | 本项目落地 |
| --- | --- |
| 交互 | 现有 Web，后续 Figma 确认后接入；本阶段 API/自动化验收 |
| 产品 | 项目、会话、作品、目标版本、修改提案 |
| 编排 | 父提案、子任务、受控工具、预算与状态检查、hooks |
| 模型 | 配置化理解/文案/视觉模型，角色输入输出严格校验 |
| 集成 | 图像网关、OCR、本地排字/导出、登记素材 |
| 数据 | SQLite 中不可变版本、执行记录、事件及素材索引 |
| 基础设施 | 本地 API + worker + 文件；生产身份/对象存储/部署另验收 |

消息与选中对象进入产品层 → 编排选择查询或修改 → 必要时模型提出结构化行动 → 工具检查目标/权限/预算并执行 → 保存新版本、事件与产物 → 返回可审结果。安全与可观测性贯穿各层。

## 已确认的执行边界

- 明确生成在已有授权范围内执行；问题反馈先检查，不直接重生。
- 修改需要同时明确对象、动作和作用范围；歧义返回候选原文与位置，不要求用户懂主副标题术语。
- 本地能改则本地新版本；需要再付费或扩大范围先确认。
- 超时未知先查记录，不自动重发；父子共享预算与权限，外部动作不由模型置信分放行。
- 无字原层、准确坐标和对象 ID 缺失时，说明不能无损编辑；不把普通 PNG 冒充原生分层设计。

## 工程底线与验收状态

本轮开始时已有测试仅代表上一轮范围。新增契约将执行边界单测、数据库事务与恢复测试、真实本地图片导出测试；涉及新增模型契约再进行预算内真实冒烟。没有真实模型证据不得标为完成。

身份、多租户隔离、金额报价和生产部署仍需专项实现/确认；不新增实际扣款、订阅、外发或上线操作。文案和模板美术验收仍由用户审核，不能拿几何校验替代。

## 首批开发顺序

1. 原生画布对象、版本、目标解析、局部排字与导出，堵住改错对象与付费回退。
2. 在上述工具上接受控父子提案、持久化状态、模型使用记录与异常处理。
3. 扩展审核模板、全案和其他后台业务合同，逐项验证后交前端阶段。

上述顺序不缩减已确认范围；未达成部分保持待开发，不用空接口充数。

## R7：三入口与 PE 一致性修复

本批在原架构上修复执行合同，不引入新框架或新付费模型。对应 R02/R04/R05/R09/R11/R12/R13/R16 的部分缺口：

- `output_contract.detect_output` 区分作品、元素、参考、否定和显式切换；全案列表不再取最后一项。当前输出被否定且未给替代类型时，intake 返回 `OUTPUT_NEEDS_CLARIFICATION`，在理解调用前结束。
- 计划和任务保存 `entry_mode`，与 `output_type` 分离。全案只包含一项仍回全案，旧记录按创作快照兼容。
- 现有专业页发送 plan_id、plan_hash、稳定 request_id 和 allow_fallback=false；确认带 hash。历史任务按 design_plan_id/generation_contract 读取方案，不先显示最新方案。旧失败/暂停任务的“查看任务”仅 GET 原任务，不重新 POST，避免历史请求键变化造成新计费。旧后台 latest 接口仍兼容，非所有旧客户端都已升级。
- 专业 DesignPlanCreate 新增单项 output_type 和 render_mode，默认仍五图/真实素材，Logo 使用示意模式。草稿复用要求事实、输出、风格、渲染模式全部相同；FactUpdate 可显式 show_price=false。旧专业分析入口的素材和通用信息门槛仍需下一批统一。
- `image_generation.build_visual_prompt` 是实际运行编译入口：区域坐标与排字读取同一 plan.layout.regions；不再用 copy_x 推测左右布局，也不对非餐饮或 Logo 强加食物近景。坐标对模型仍是要求，不是已验证的像素约束。
- 生成调用前写 `generation-request.json`，含实际 prompt/hash、计划、provider/model、尺寸和编译版本；失败也有证据。模型返回后先保留原文件与审计，OCR/排版失败记录 failed，不把“有文件”视为视觉通过。文件属于本地项目数据，不默认推送或对外暴露。
- 质量失败不改为付费重试；诊断仅根据已存证据回答，无成品时不提示“上方预览”。计时标签改为“生图与后处理”，明确不包括整个理解和排队过程。

回归入口：`backend/tests/test_p0_entry_pe.py`、`frontend/tests/generation-binding.test.mjs`、`frontend/tests/p0-entry-smoke.mjs`。浏览器脚本使用独立 Chrome profile，拦截并模拟所有业务 API，不写真实项目、不调用模型。

本轮未执行数据库迁移、常驻服务切换、外网部署、付费模型验收或 GitHub 推送。真实底图文字、主体遮挡、文案吸引力和时间目标须在另行授权的样本预算内验证，不能用单测数替代。

R7 实际验证：全后端 270 项通过；前端 20 项通过；TypeScript 检查通过；隔离 Chrome 完成一键/全案投诉不生成、全案单项续作归属、专业历史方案恢复与只读失败查看、新操作显式绑定回归。以上浏览器业务接口全部模拟，不代表真实模型与常驻后端联调已完成。
