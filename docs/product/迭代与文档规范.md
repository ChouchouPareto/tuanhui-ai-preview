# PRD 持续迭代与文档质量规范

状态：本次建立的项目工作约定；适用 PRD、专题方案、评测、模型记录及开发交付。

## 单一主线

- 主 PRD 固定为根目录 `PRD.md`，正文持续优化，修订号 R1、R2……递增；软件版本独立。
- 专题文档不是平行 PRD：需求在 PRD，实现状态在 `requirements.json`，结果在具体测试/评测报告。
- 需求 ID R01～R20 保持稳定；拆分可增加子项或新 ID，已删除需求保留变更说明而非回收 ID。
- 快照只增不覆盖。历史文件只作为证据，不作为新的默认需求来源。

## 每轮工作

1. 定位当前工作目录和 Git 基线，读主 PRD、需求追踪及本任务关联专题。
2. 判断请求是咨询/文档还是代码开发；不以文档要求自动授权付费调用、发布、退款或全局配置修改。
3. 修改前运行 `node scripts/product_docs.mjs snapshot before-标签`；PE 运行代码变更另用既有 `scripts/backup_pe.py` 备份。
4. 记录变更来源和需求 ID；区分用户已确认、历史待确认、作者建议、代码事实、实测证据。
5. 在同一主 PRD 修订，不再开新的全量 PRD；同步受影响的专题、案例和状态。
6. 文档检查 `node scripts/product_docs.mjs check`；代码变更按风险运行相关测试，未运行要说明。
7. 更新 CHANGELOG：背景、修改、理由、替代方案、影响范围、验证、剩余事项。
8. 创建 after 快照，最后向用户复述做法与待审核点；快照和本地修改不等于已推送远程。

新建主线的第一次不存在旧 PRD.md，保留旧 V0.8 原文件作为迁移来源；首次 after 快照成为主线初始基线，不假造 before 快照。

## 文档质量门槛

| 维度 | 要求 | 不合格示例 |
| --- | --- | --- |
| 可追溯 | 需求 ID → 用户/资料来源 → 决策 → 实现锚点 → 测试 | “参考课程，已优化”无页码/章节 |
| 可执行 | 输入、输出、正常/异常状态、权限、费用与验收明确 | 只写“智能识别、体验好” |
| 可比较 | 候选、参数、样本、失败分母、成本口径一致 | 用不同测试集宣布模型胜出 |
| 可验证 | 文件/请求/日志或报告证明实现 | 有按钮就说完整功能已完成 |
| 诚实 | 未知/建议/未测明确标注 | 填入猜测成本、准确率和课程结论 |
| 一致 | 同一规则只有一处主定义，其他链接引用 | 全案在一份文档独立，另一份仍混在单项 |
| 可维护 | 固定入口、稳定 ID、版本与不可覆盖快照 | 每轮一个新主 PRD，读者不知道看哪个 |

## 验证状态

实现状态：`code_exists`、`partial`、`not_implemented`、`deferred`、`pending_decision`、`docs_ready`。

验证状态：`not_run`、`historical_report_only`、`static_review`、`offline_passed`、`browser_passed`、`model_evaluated`、`user_accepted`。状态升级必须有可检查证据和时间；一项单测不能升级整项需求为用户验收。

维护者写入新证据时检查代码是否已变化；若已有结论失效，保留原报告、更新当前状态为待复验。不要用旧测试数字作为今天重跑的结果。

## Codex 接入边界

项目根 `AGENTS.md` 提供简短入口和规则，不塞整份 PRD。后续从正确仓库根目录启动 Codex；若旧会话未加载新规则，应明确让其读 `AGENTS.md` 或重新开始会话。其他机器需同步这些文件后才有相同项目指导，不是全局自动广播。

依据 [OpenAI 官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：项目指令参与启动时的指令链，目录和覆盖文件会影响加载。本轮只创建项目文件，未更改用户全局配置，也未启动另一个付费 Codex 会话验证加载。

## 完成后复述模板
