## R1 · 2026-09-15 · 建立持续迭代主线

### 来源与目的

用户希望整理多轮需求、意图与动作路由，并为课程方法、评测、模型选型和架构论证准备高质量文档；在同一 PRD 持续迭代，供后续 Codex 使用。实现核对基线为 64deee5，未更新软件版本。

### 本轮变化

- 新建固定入口 `PRD.md`，整合为 R01～R20。旧 V0.1～V0.8 PRD 及版本化 PE 保留，不覆盖。
- 明确一键单项、专业创作、独立全案边界；将专业版基础错误提前，而不推迟到无限画布之后。
- 明确“发送 ≠ 生图”，先补路由、目标、授权、诊断与本地修复，再考虑父子 Agent。
- 配套架构决策、模型选型/Token 成本口径、评测门槛和 40 条人工构造种子案例；没有填写虚构评测成绩。
- 保留历史商业化、人工保障、平台发布等需求为待确认，不因本次聚焦而删掉。
- 建立来源登记、课程接入流程、项目级 AGENTS 指引及不可覆盖 Markdown 快照工具。

### 为何这样做

多个平行主 PRD 会产生“哪个版本算准”的冲突；只补 PE 不能修复权限和执行层错误。固定主线、分离专题和状态，让产品意图、实施证据及验证结果各有归属。

### 验证与剩余

本轮实际验证：`node --test scripts/product_docs.test.mjs` 8 项通过；`node scripts/product_docs.mjs check` 检查 14 份文件、48 个本地链接、20 项需求、40 条种子案例通过。初次检查发现校验工具误将目录链接当成文件，已修正并补目录链接测试。`git diff --check` 通过（Git 对未跟踪文件的检查范围有限，新增文档另由上述工具校验）。

测试脚本只检查文档结构/数据/备份，不运行产品路由或付费模型。课程资料待提供；实际模型选定、测评 runner、业务代码修复和正式 Figma/编辑器均未因本轮文档工作完成。

本轮不修改业务代码、全局 Codex 配置，不付费调用、不提交或推送 GitHub。现有用户数据变更保留。

首次主线不存在 before 版本；旧 V0.8 文件是迁移来源，after 快照作为新主线基线。后续 R2 起修改前后均备份。
