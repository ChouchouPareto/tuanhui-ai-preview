# 单项入口与全案工作区迁移 v0.11.2

日期：2026-09-13。范围：前端交互迁移；后端生成合同仍为 v0.11.1。本次不调整 PE、模板或计费接口，不触发真实模型调用。

## 已落实

- 一键生图 `/`：只选择一种图片类型。五连图、三连图、Logo、套餐、代金券、菜品、宣传、首页装修、详情页；没有全案选项或组合勾选框。详情页仍可在同一种类型下指定多张。
- 类型选择放在输入框底部。文字左侧小尺寸淡紫玻璃下拉图标；浮层属于输入框 DOM，锚定按钮，不再出现右侧独立大面板。
- 选择单项后收起，Escape 收起并返回按钮焦点，点击外部收起；移动端用点击操作，不依赖悬停。展开不改变输入框高度。
- 全案设计 `/full-plan`：独立可访问的临时工作入口，保留默认代金券、五图、Logo及自选组合，复用既有输入、授权、队列、取消、结果、预览、下载和续作逻辑。
- 首页三个端口及侧栏入口接通全案页面；全案的「新建创作」「继续下一次创作」留在全案路径。跨端口创建新需求携带已有项目，保留服务端素材和作品，不会自动开启生成。
- 历史 `/?project=…&creation=…` 全案链接读到 `output_type=full_plan` 后转到 `/full-plan`，保留项目/创作标识，不迁移或重写数据库，不再次生成。

## 后续正式页面的替换点

- `frontend/app/full-plan/page.tsx`：正式全案页面入口。目前复用工作区壳，明确标记临时版，不是最终视觉设计。
- `frontend/app/studio-output-picker.tsx`：共享输入框设置组件。`fullPlan=false` 单选类型，`fullPlan=true` 多选交付项目。
- `frontend/lib/output-options.ts`：输出类型名称与全案默认组合。
- `frontend/app/m1-review.tsx`：需求修订、授权及任务恢复，后续正式页面可以继续复用或抽为 hook。
- `creation_api.py` 的 `delivery_types` / `approved_image_calls` 以及生成服务 `execution.kind=bundle`：保持现有程序执行合同，不是父子 AI Agent。

正式全案开发顺序：Figma 完整页面与状态流程 → 用户审核 → 替换临时壳；不把这个临时页面当成正式设计规范。输入状态、生成任务与布局渲染需要保持分离，不因换 UI 改写旧作品。

当前跨路由进入另一端口是新需求入口，不继承另一端口尚未提交的本地文件选择；已保存素材和作品不受影响。未来正式工作区应定义草稿跨端口携带策略。
