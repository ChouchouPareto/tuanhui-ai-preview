# 对话安全路由 · 首轮修复交付

日期：2026-09-15。对应主 PRD：R02、R04、R05、R06。状态：首轮代码与离线回归完成，待用户验收；不是完整语义 Agent，也不代表图片美术质量已解决。

## 1. 本轮解决什么

用户在已生成作品下反馈“文字重叠”“还是这样”，不应直接弹生成费用确认，再生成一遍。本轮先补对话到执行之间的安全边界，不扩展父子 Agent、构图模板库或无限画布。

## 2. 根因与发生环节

原链路把消息提交近似当成一次新创作：前端先处理生成授权；续作创建子版本并继承旧事实；资料达到 ready 后触发自动生成。旧店名、用途与素材完整，并不意味着这条新消息要求生成。问题发生在“消息意图 → 动作选择 → 授权 → 执行”的衔接，而非只换几句 PE 就能解决。

另外，仅在前端改按钮无法防止旧入口或直接请求绕过，所以本轮同时增加服务端 intake 和确认前的保护。

## 3. 新的执行流程

1. 用户发送消息，先进行本地安全路由，不调用付费模型。
2. 绑定 URL 指向的项目、创作或任务；有多份作品且无法定位时询问，不擅自选择最新一份。
3. 问题反馈、咨询、进度、费用询问、否定生成及不明确的续作进入回复/检查，不创建生成任务。
4. 检查只读取任务状态、已存模型调用记录及产物/排字检查记录，不调用视觉模型、不修改旧作品。
5. 明确的新创作、支持的换风格请求才继续原授权与生成流程。路由接口失败时停止，不降级成直接生成。
6. 支持的明确标题替换走本地排字路径；设置 local_only，条件不满足时返回说明，不悄悄改为付费生图。

“取消”类对话只解释如何停止；真正停止使用独立停止按钮。生成中可以继续询问进度，发送消息不再等同于停止。

## 6. 尚未完成，不能混为本轮成果

- 当前是规则式安全路由，不是完整语义路由；复杂表达可能被保守拦下。下一步用结构化模型提案配合服务端动作白名单，而不是解除保护。
- 只检查已存记录。没有原图/检查报告时明确证据不足；saved OCR passed 不能证明用户当前看到的文字没有重叠。
- 尚未实现截图视觉诊断、自动去字、通用局部修图和任意区域排字修复。文字重叠、美术质量和文案吸引力仍需单独闭环验收。
- 支持有限标题替换，不覆盖任意副标题、价格、字体和布局修改；本地资源不可用时不承诺一定能修好。
- 完整预算合同、报价、供应商未知结果恢复及多租户鉴权仍未完成；对话日志还没有独立客户端幂等键。
- 文档里的 40 条种子案例没有全部接入统一 runner；本轮 37 项新增回归不等同于整套模型评测。
- 专业版剩余流程、Figma 审核后的全案正式页面、父子 Agent、正式构图库、无限画布未在本轮开发。

## 7. 后续开发次序

1. 在现有保护上接结构化意图/对象/动作提案，扩展否定、局部修改、多轮指代与成本评测，保持服务端校验。
2. 图片问题证据闭环：定位原图含字、程序排字、裁切、预览的具体责任环节；本地可修优先复用，并保留版本。
3. 统一耗时、预计等待、请求状态及 Token/调用计量；未知结果先查，不自动重试。
4. 修专业创作基本可用性，再推进已确认的模板/编辑器设计；需要 Figma 的工作先出图审核。

建议用户验收：打开已有作品输入“文字重叠了，为什么？”；应先收到检查回复，不出现生成授权、不新增图片。生成中输入“还要多久？”应能回复，任务继续运行；要停止则点击独立停止按钮。
