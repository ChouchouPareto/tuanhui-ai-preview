# 千问受控编排与功能工作台

对应主 PRD R8；本地功能预览，不是完整目标版本验收或正式上线。

## 本轮授权与范围

用户要求先补齐功能，模型优先全部千问，正式 Figma 与视觉后置，临时端口可以简洁。付费验收上限为 3 次语言理解、3 次生图，不自动重试。经营后台、订阅积分、平台代发布没有据此获得新实施授权。

实际使用：3 次 `qwen-plus`、1 次 `qwen-image-3.0`；剩余两次图片额度未使用。没有额外 OCR/VL、文案子模型或自动补跑。两次理解过度澄清未进入生图，不能用剩余图片额度假装这两条完整模型链路通过。

## 可操作入口

- `http://127.0.0.1:3011/workbench`：项目、三个入口、单项/组合选择、素材用途、事实、语言预算、方案核对、图片预算确认、执行状态、历史、预览下载。
- `/workbench/editor?project=项目ID`：原生画板、生成作品导入、文字对象选择、坐标/字号/颜色/层级、锁定、移除、历史恢复、复制、切片 ZIP。多画板位置、缩放与视口可记录保存。
- `/workbench/templates`：已有坐标模板的区域示意、原始合同、按内容指纹记录审核。不是稿定案例拆解稿，未替代 Figma 审核；审核记录暂不作为生产发布门禁。

首页增加功能工作台链接，旧流程保留。新工作台 CSS 使用独立命名空间，不覆盖旧 `.workbench` 布局。

## Input → Output

1. 用户选择项目、入口、输出范围，提交当前消息、明确事实、素材 ID、可选目标任务/对象、语言调用预算。
2. 本地优先识别投诉、咨询、进度、取消；这类问题读已存证据，不进生图授权。
3. 持久化 `AgentRun` 和对应 `WorkflowTask`；请求内容指纹及 request_key 防重复；入队必须有可用 worker。
4. worker 按排队时间从理解、一键/全案、专业三个队列取任务，用条件更新领取。
5. 可选千问父任务读取有限 JSON 上下文，输出意图、带原文证据的事实、文案草稿或修改提案。父模型不能执行任意工具或自行批准费用。
6. 可选文案子任务使用独立的事实/类型/风格上下文，不复制完整父对话、不传案例图；本轮最多两个语言请求，调用前记账。只授权一次时不调用这个子任务。
7. 程序核验事实原文、草稿容量、素材归属，整理创作快照。布局、费用、裁切和排字由程序控制，模型的对象 ID 与输出内容不直接执行。
8. 返回待确认资料、缺口、交付项和 snapshot_hash；没有用户确认不请求图片模型。
9. 确认接口绑定快照与图片调用上限，复用现有持久队列、构图预约、素材指纹、无字检查、程序排字与导出。
10. 编辑已有对象先生成绑定版本的提案，用户确认后应用；保留旧版，不把本地文字修改变成重新生图。

三入口共享执行安全，但新工作台显式选择的范围不再被消息中的子类型覆盖。全案选一项仍保存 fullplan；专业选无实拍示意不再被模式硬拦截。旧自动解析入口继续使用 auto 策略。

## 本轮真实验收发现与修复

| 入口 | 实际理解 | 实际生图 | 结果 |
| --- | --- | --- | --- |
| 一键五连图 | 1 次，3.554 秒 | 1 次，模型请求 3.280 秒 | 技术任务成功；含排队、理解、生成、导出的脚本墙钟 14.18 秒 |
| 专业三连图 | 1 次，3.653 秒 | 0 次 | 父模型错误要求三个画面分别的内容、已有对象/参考图 |
| 全案只选首页装修图 | 1 次，3.335 秒 | 0 次 | 父模型因 objects 为空要求先提供已有设计对象 |

根因：初版父 PE 中“没有对象就澄清”的编辑规则未限定意图；新建请求也发送了 `objects: []`，且没有告诉模型允许示意、排版由模板程序负责。模型把编辑前置条件套给新建，造成无必要追问，并误把三连图当成三个分镜。

修复：`parent_context` 区分 new_creation / resolve_edit；新建不传对象键，传完整母版规格、允许示意、价格展示、交付项和模板负责方；PE 明确新建不得索要已有对象或逐片内容。编辑才发送版本和对象。已做离线合同回归；受本轮额度和“不重试”约束，修复后尚未重新做真实语言验收。

本次五连图人工查看：未见原先双层文字叠印；但主体集中于左侧、较大留白、标题词组被拆行、面食呈现偏通用示意。技术成功不代表美术/商家接受。已优化本地文字换行，优先在现有标点/短语边界分行、不删字；旧产物未覆盖。构图覆盖、餐饮地域/菜品保真和吸引力仍需扩充评测，不据单样本修改为“全部已解决”。

## 状态与收费边界

- `QUEUED → RUNNING → SUCCEEDED / NEEDS_USER`；用户可取消 QUEUED/RUNNING，晚到模型响应保留用量但不能复活任务或继续生成。
- 过期租约转 NEEDS_USER，不重新发请求；超时未知仍算一次已占用预算。
- `SUCCEEDED` 对理解任务只代表处理结束；可能结果是 clarify，不代表已交付图片。
- 父与子分别保存 model/contract/status/token/duration；阶段事件保存排队、理解、文案、工作流。估时样本不足时不捏造倒计时；3 分钟仍是目标，不是 SLA。
- 请求失败/格式错误/证据不符不重试、不换模型，不把模型缺失用量记成零元。
- 代码可调用 2 次语言是产品能力；本轮真实验收每入口只授权 1 次，脚本有独占 started 记录，重复运行不能增加本轮调用。

## 实现、测试与本地搭建

核心代码：`agent_schemas.py`、`agent_api.py`、`services/agent_runtime.py`、`prompts/agent_parent_v1.md`；迁移 `a5e9c1d3f7b2` 新增 agent_runs / workspace_states / template_reviews。

实际验证：后端 280 项通过；前端原有 20 项通过；TypeScript、工作台范围 ESLint 和隔离生产构建通过。Chrome + 隔离真实 API 的工作台冒烟覆盖零调用准备、投诉、画板创建、改字、布局保存、390px 窄屏、模板区域；该项目模型调用记录为空。全仓 ESLint 仍需独立清理旧页面问题，不将范围检查冒充全仓通过。

验证命令：

```sh
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests -q
cd frontend
npm run typecheck
npm run test:confirmation
NEXT_BUILD_DIR=.next-verify ./node_modules/.bin/next build --webpack
```

`scripts/workbench-smoke` 的实际路径为 `frontend/tests/workbench-smoke.mjs`，默认连接 3011 前端并把 API 请求导向隔离的 8021；禁止理解付费与图片确认请求。不要对真实用户项目运行破坏性测试。

本地数据库升级前用 SQLite backup 保存到 `runtime_logs/workbench-acceptance-20260921/pre-upgrade-user.db`。升级前后现有项目均 18 个、任务均 49 个。现有 8011 API 和 worker 已更新；3011 仍为原前端服务。服务只绑定 127.0.0.1，没有上线公网。

后续在端口空闲时可用 `.venv/bin/python scripts/start_local.py` 同时启动 API/worker/前端；端口占用则退出，不自动终止其他进程。控制台退出会停止自己启动的子进程。单独迁移使用 `PYTHONPATH=backend .venv/bin/python -m alembic -c backend/alembic.ini upgrade head`，先备份。

真实记录位于 `runtime_logs/workbench-acceptance-20260921/receipts`，隔离图片与数据库在相邻目录；默认不提交这些数据到 GitHub。用量表共四条真实供应商调用；未伪造价格或按 Token 换算图片费用。

## 尚未达成的目标版本范围

1. 新建/编辑 PE 修复后的真实复验；三个完整模型链路及用户认可的视觉质量。
2. 更完整的语义追问、跨轮证据、视觉局部编辑与布局对话。当前本地对象可改，不具备通用图片物体拆层或局部重绘。
