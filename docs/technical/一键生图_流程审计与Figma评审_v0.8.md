## 1. 结论

当前不是自然对话驱动的生图 Agent，而是“五字段抽取 + 规则校验 + 固定回复 + 单独确认接口”。只改提示文案或接一个更强的模型，不能修好动作路由和页面结构。

新方案：用户说一句话或发素材 → 独立对话工作区理解 → 内容足够且费用已授权即生成 → 输出连续长图与五切片 → 对话或点选修改。只有无法安全选择的关键信息才追问。

## 3. 为什么点击和对话都走不下去

1. 首页底部箭头调用 `revise()`，只提交整理需求。真正执行生图的是摘要里的“生成五图”按钮，调用 `/confirm`。
2. 没有把“确认、开始、就这样”路由为执行意图。文字仍进入抽取，随后返回同一固定答复。
3. `conversation_reply()` 是分支拼句，不读取完整自然对话意图，不能解释动作，也不会自动执行工具。
4. “先做 AI 示意图”按钮只把文字放进输入框，还要再发送。后端只识别特定正则措辞，不是开放式语义理解。
5. 草稿与摘要不一致时隐藏生成入口；用户继续输入“确认”，反而触发新一轮整理。
6. 已确认的 creation 被锁定，新版本需要明确创建新任务，否则继续修改会报 `CREATION_LOCKED`。

## 4. 所有已查到的阻塞条件

审计范围：当前首页对话 → intake → confirm → 生图/排版主链路；不把旧备份当运行逻辑。

| 条件 | 现状 | v0.8 处理 |
|---|---|---|
| 店名 | 展示店名时必须有；一键模式没有店名默认不展示 | 保持可选；不要求为填表而补店名 |
| 主推内容 | 无可渲染菜品素材时，要求菜品/卖点/定位之一；示意模式已有店名可豁免 | 素材、主题、品牌、品类任何一个可支持设计即可开始 |
| 真实照片 | real_assets 默认至少一张 `product + dish/signature_dish` | 不普遍必填；无实拍走已告知的 AI 示意/品牌氛围路径 |
| 门头、菜单 | recognition_only，不能替代菜品入画 | 保留门头不入成品；允许品牌主题继续，不强迫补菜品 |
| 素材语义 | 主链路依赖已存分类，不等于此处重新视觉识别 | 新方案按内容判断用途，保留用户纠正入口；不能仅相信上传位置 |
| 价格 | 要展示才要求；有数字不代表业务真实性已验证 | 默认省略；用户后续明确修改覆盖旧值；真实冲突才问 |
| “或”类文字 | 字段含“或/还是/待定”等可触发冲突 | 不能把字面“或”当冲突证明；判断是否真有两个未决事实 |
| 示意图模式 | 依赖完整匹配“使用/做/生成…AI 示意图” | 语义意图或直接按钮动作，点击即生效，不填入暗号等再次发送 |
| 自由回答 | 旧 reply 分支拒绝“不知道/随便/你决定” | 对风格、布局等允许委托系统；价格等不能瞎猜 |
| 智能理解授权 | `use_ai` 需要 policy；首页非空文字默认调用 | 费用与会话授权集中处理，不用技术开关控制理解能力 |
| 第二次确认 | ready、materials_confirmed、policy 等参数 | 将合法授权记录与“开始生成”动作合并；不重复确认同一需求 |
| 幂等与 revision | 请求键、snapshot_hash、revision 必须一致 | 保留服务端安全约束，前端自动协调；不能撤掉防重复扣费 |
| 素材安全 | 归属、路径存在、内容哈希、分类变更检查 | 保留；指出具体失败素材，允许替换/移除后继续 |
| 长度 | 单次/拼接历史 8000 字；素材 IDs ≤20；结构化字段 ≤500 字 | 不让历史累加挤占用户输入；摘要压缩、附件单独存储 |
| 排版容量 | 文字超出母版时抛错要求缩短 | 自动适配字号/布局；不得擅自改价格，必要时询问删哪段 |
| 生图前提 | 无真实菜品且非 illustration 会被后端拒绝 | 两种渲染模式端到端一致，不能仅 UI 放行 |
| 配置/服务错误 | 密钥缺失、模型错误、超时均可能中止；部分提示仍要求关闭已删除开关 | 明确重试/基础版/保留草稿出口，不给不存在的按钮指路 |

安全校验和付费授权仍需存在，但不应被包装成用户必须填写第二张表。

## 5. 当前调用哪个 AI、消耗多少 token

本地配置读取结果（未输出任何密钥）：

| 功能 | 模型/实现 | 限制 |
|---|---|---|
| 文字理解 | `qwen3-vl-plus` | 只发送文字 JSON；当前这一调用没有图片、没有真正对话工具 |
| 用户看到的回答 | Python `conversation_reply()` | 固定文案，不是模型回复 |
| 默认生图 | `qwen-image-3.0` | 图片模型，不负责对话状态推进 |
| 豆包生图配置 | `doubao-seedream-5-0-260128` | 不能因为配置存在就说本次已调用 |
| 长图/切片 | 本地排版服务 | 母版 4000×600，切为 5 张 800×600 |

每轮会把历史用户文字重新拼接发送，既增加 token，又让过时事实和新指令混杂。当前 `_post_chat` 设 temperature=0，但没有应用级输出 token 上限。下一版建议：本地操作意图零模型调用；一轮主理解；必要时最多一次有预算的结构修复，禁止无限自我循环。按任务记录输入/输出/缓存/图片等实际 usage，缺失标记为未知而非 0。

## 6. 为什么整个框还会变长

`.conversationThread` 位于首页 `.quickPrompt` 内，M1Review 把消息、摘要、生成按钮和结果 portal 到这个区域。420px/40dvh 是最大高度，不是固定工作区高度。消息增长时仍会增加父框高度；底下还有 textarea、工具栏和费用说明。之前 `align-items:start` 只修了左侧素材跟随拉伸，没拆开整个架构。

新布局约束：

- 首页只保留紧凑入口，发送后进入独立创作页。
- 创作页采用视口高度布局：头部固定，内容区 `minmax(0,1fr)` 独立滚动，底部输入栏不随消息增长。
- 输入正文最多 4–6 行，超出在正文内部滚动；素材缩略图一行，不出现与聊天同高的上传竖柱。
- 桌面稿 1440×960；手机稿 390×844。手机考虑 safe-area 和键盘，输入栏随可视视口上移，历史消息高度缩减。
- 结果留在内容区。放大查看/局部修改进入结果详情，不在 textarea 内展开。

## 7. 新交互：用户具体怎么操作

| 场景 | 用户操作 | 系统表现 | 还需要什么 |
|---|---|---|---|
| 一句话完整需求 | “给袁记云饺做团购五连图”→开始生成 | 进入工作区，明确品牌氛围/AI 示意，开始执行 | 已授权且报价在范围内，无再次确认 |
| 只有真实菜品图 | 加照片→开始生成 | 识别画面内容，自动布局，省略未知店名和价格 | 不强制填写套餐或店名 |
| 只有门头 | 加照片→开始生成 | 提取店名；不把门头画入成品；生成品牌氛围版 | 可补菜品，但不是阻塞项 |
| 纯文字没素材 | 描述主题→开始生成 | 默认告知 AI 示意，不冒充真实菜品 | 真实商业事实不能编造 |
| “帮我做图”/无有效主题 | 发送 | 问“想给什么店做？说个品类或发张照片就行” | 只缺方向；用户回答后继续，不再重问 |
| 两个真实价格冲突 | 用户从两份资料中要求放价格 | 问一次选择；也可“不放价格” | 点选就是提交，不需再次发同一句 |
| 初次未授权/超预算 | 点击开始 | 显示准确报价与本次范围，授权后执行 | 只在必要的费用节点确认 |
| 生成中 | 可停止/离开 | 保存任务；重进查看状态，不启动新调用 | 上游停止能力如实说明 |
| 生成完成 | 下载或说“第2张标题小点” | 局部修改并保存新版本；长图与切片一起更新 | 纯排版不应调用图像模型 |
| 要修改图片内容 | 点图片位置→描述修改 | 显示所选区域和新报价，在原授权内执行 | 局部图像编辑能力需另实现、验收 |
| “确认/开始/就这样” | 输入自然语言 | 若存在明确待执行方案且有授权，执行一次 | 无待执行对象时才解释，不做盲目扣费 |
| 失败 | 重试/改需求/返回项目 | 保留资料；先查任务再重试，避免重复收费 | 不要求整段重新输入 |

日常用户不会写标准化 PE。输入示例只应作为灰色占位，不自动塞进正文。可供内部测试的完整样例：“给袁记云饺做一套团购首页五连图，清爽暖色，不放价格，没照片先做品牌氛围示意。” 普通用户说“袁记云饺，五图”“用这些图做”“清爽一点”也必须进入同一链路。

## 8. PE 与模型职责的优化设计（尚未开发）

一句话：让模型理解意图，让业务层决定能否执行，不让字段校验器伪装成聊天。

主理解输入：当前用户消息、当前 brief 摘要、必要的最近对话、素材用途及识别结果、当前任务和版本、允许的动作。上传原图不每轮重复发送，视觉识别按内容哈希缓存。

输出契约建议：`intent`、`brief_patch`、`evidence`、`assumptions`、`blocking_question`、`next_action`、`user_reply`。事实与设计假设分开；“确认”绑定明确的待执行 proposal_id，不能单凭一句文本任意调用收费工具。

主提示词原则：

> 你是团绘的创作助手。用户想尽快拿到图，不是填写资料。结合已知内容理解本次意图；用户提供品牌、主题、品类、卖点或可用素材中的任意一种，足以形成设计方向时就推进。缺失价格、店名、套餐不普遍构成阻塞，省略即可。不得虚构价格、优惠、销量、荣誉、官方 Logo 或真实菜单。门头仅用于识别，不进入成品。无照片可用已告知的 AI 示意方案。设计选择可代用户决定，商业事实不可猜测。真正影响执行且无法安全省略时只问一个简短问题，不重复询问已知内容。自然语言回复应简短说明下一步；结构化 next_action 由服务端校验后执行。未收到工具成功结果不得声称已生成。

后端状态建议：`DRAFT → UNDERSTANDING → NEEDS_INPUT / NEEDS_AUTHORIZATION / GENERATING → SUCCEEDED / FAILED / STOPPING / STOPPED`。用户修改另存新版本，恢复项目只读取任务。

图像 PE 分层：已确认事实 → 全局色彩/字体/光影/布局契约 → 连续母版 → 文字后置 → 切片 → 跨缝、乱码、事实、主体一致性检查。不要把五张独立场景拼起来冒充连续母版。

当前生图 PE 在实拍模式下只生成抽象背景，菜品和文字由本地合成；示意模式只有店名时又禁止生成具体菜品。因此单纯更换理解模型不会自动提高菜品真实性或版式质量。

更聪明的模型需要通过中文省略表达、纠错、多轮指代、素材理解、结构化动作和延迟测试再选型。本次核实了现用模型，不依据即梦截图臆测其内部模型，也未直接更换付费供应商。

## 9. 设计稿范围与非目标

18 个桌面状态：主页、素材、理解中、必要追问、直接生成、生成中、结果、局部修改、修改完成、失败、门头-only、价格冲突、首次授权、停止、项目恢复、理解失败、上传失败、积分不足。4 个手机状态：主页、追问、生成中、结果。

结果里的图是本次设计的品牌氛围 UI 示意，不是模型实测成品；报价 10 积分和余额 6 积分只是交互演示，不是正式定价。Figma 是评审原型，不是已上线的编辑器或计费系统。

此次使用 UI 技能落实可见动作名称、固定输入/独立滚动、44px 点击区；使用产品拆解技能区分竞品页面事实与设计建议。沿用当前代码的浅灰、白色、黑色主按钮；不照搬早期 MASTER 文档的紫底青色按钮。中文采用 Figma 可用的 Noto Sans SC，代替未提供的 PingFang 字体；库按钮保留 Inter。

## 10. 开发前验收清单

1. “袁记云饺，五图”在已授权范围内一次操作进入生成，不循环回复。
2. 仅素材、仅品牌、仅卖点、无价格、无店名的可生成路径均有测试。
3. “先做示意图”“没照片你画”“用这些素材”不依赖固定暗号。
4. “确认”只执行明确待执行方案一次；双击、刷新、重进不重复扣费。
5. 20 轮聊天后输入栏与素材缩略图尺寸不变；桌面与手机均可用。
6. 价格明确改动使用新值；真正冲突才追问；不重问已知信息。
7. 文字理解失败、上传失败、余额不足、模型超时均能恢复且不丢资料。
8. 门头不入成品，AI 示意不冒充实拍；整张长图裁切与五张文件一致。
9. 修改生成新版本；纯排版变化不调用付费图像模型。
10. 每次模型调用有 usage 和任务归属；失败和未知费用不记成免费。
