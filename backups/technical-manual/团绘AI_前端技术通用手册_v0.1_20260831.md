# 团绘AI前端技术通用手册

> 当前版本：V0.1  
> 版本日期：2026-08-31  
> 适用范围：团绘AI Web/WAP MVP、后续微信小程序迁移前的前端开发  
> 上位资料：《团绘AI_PRD_v0.7_竞品启发优化版》《AI产品Vibe Coding通用前端技术栈手册 V1.0》  
> 文档性质：项目级长期技术约束；不替代单阶段开发文档、接口契约和验收记录

## 0. 使用方式

每次进入新的前端阶段，按以下顺序执行：

1. 读取最新 PRD、本手册、后端阶段文档、真实接口及本轮视觉参考；
2. 先更新本阶段的范围、状态矩阵、接口与验收清单；
3. 只按一个可运行的业务闭环开发，不以页面数量拆阶段；
4. 完成类型检查、测试、生产构建和真实浏览器验收；
5. 记录修改文件、检查结果、已知问题与回退方式；
6. 对本手册的变更必须升级版本，历史版本不得覆盖。

资料冲突时，优先级为：产品负责人本轮明确要求 → 已确认 PRD/验收标准 → 已确认视觉参考 → 后端真实能力与接口 → 现有工程 → 本手册默认方案。

## 1. 产品与当前阶段判断

- 产品类型：本地生活餐饮视觉包生成 Agent 工作台。
- 核心用户：单店商家、连锁运营、代运营人员；BD 是种子用户群体，不设置专属入口。
- 首发终端：桌面 Web 与移动 Web；结构需为后续小程序迁移保留业务层边界。
- 核心闭环：创建门店 → 上传并标记菜单/门头等素材 → 系统整理或 AI 识别 → 对话补齐 → 人工确认事实 → 后续策划、生成、校验、导出和发布。
- 当前已实现范围：创建餐饮项目、语义化素材上传、默认零模型消耗的对话采集、可选百炼识别、多门店候选、菜单事实展示、事实确认。
- 当前开发目标：先完成小云雀式代表工作台的 UI 重构，保留上述真实接口与业务逻辑；本轮不提前宣称五图生成已完成。

## 2. 前端技术适配声明

### 2.1 继续采用

| 项目 | 实际方案 | 决策 |
| --- | --- | --- |
| Runtime | Node.js 22 活跃 LTS 基线 | 本地与部署保持同一主版本 |
| 框架 | Next.js 16.3.3 App Router | 继续使用，不跨大版本升级 |
| UI Runtime | React 19.1.1 | 继续使用 |
| 语言 | TypeScript 5.9，strict | 所有新增业务类型禁止使用 `any` 逃避检查 |
| 包管理 | npm + package-lock.json | 锁定依赖，避免多包管理器混用 |
| 后端通信 | HTTP API；长任务当前轮询/按需查询 | 不为“实时感”提前引入 WebSocket |
| 表单 | 原生表单 + React 局部状态 | 动态复杂度出现前不引入重型表单库 |
| 客户端状态 | React state | 当前规模不引入 Zustand/Redux |
| 服务端状态 | 后端数据库与任务接口 | 浏览器状态不得冒充任务事实 |

### 2.2 本项目偏离通用默认方案

1. 当前未使用 Tailwind CSS。为降低本阶段迁移风险，先以 CSS 语义变量、组件类和分层样式建立设计系统；不在 UI 重构同时替换整个样式栈。
2. 当前未安装 Lucide。此次允许使用统一线性 SVG 图标组件，禁止 Emoji 充当产品图标；图标数量明显扩大时再引入 Lucide。
3. 当前没有 TanStack Query、Zustand、Radix 或 shadcn/ui。当前交互复杂度尚未达到引入条件。
4. 当前真实后端为跨端口 API。开发期保留 `NEXT_PUBLIC_API_BASE`；发布阶段必须迁移为同源代理并明确构建时后端地址。
5. 当前没有前端测试、Playwright 和可用 lint 配置，这是待补质量基线，不应被“构建通过”掩盖。

### 2.3 立即纠正的工程问题

- 把 API 基础地址、JSON 解析和错误归一化移出页面组件；
- 把 App Shell、工作区、上传器、状态提示、事实确认拆成职责清楚的组件；
- 用统一任务状态表达 `idle / submitting / waiting_user / succeeded / failed`；
- 不再把全部流程并排塞进三个等宽表单栏，改为单一主任务区与清晰步骤导航；
- 补齐加载、空、禁用、失败、成功和恢复文案；
- 项目 ID 后续进入 URL，以支持刷新恢复；在接口未提供项目列表前，不伪造历史项目。

## 3. 信息架构与页面结构

### 3.1 Web App Shell

桌面端采用固定侧栏 + 主工作区：

- 左侧品牌区：团绘AI标识、折叠入口；
- 主导航：开始创作、我的项目、素材库、使用说明；
- 历史区：只展示后端真实存在且可恢复的项目；当前接口未完备时显示当前会话，不伪造列表；
- 用户区：账号、通知或帮助入口；
- 主区顶部：产品公告、版本/额度状态、帮助；
- 中央工作区：模式切换、页面标题、单一主创作卡；
- 下方内容：能力说明、最近项目或本阶段相关提示，不堆放无关营销卡片。

移动端：侧栏转换为可关闭抽屉；主工作区单列；关键按钮宽度可触达；不得产生横向滚动。

### 3.2 当前代表页面

当前首页是“门店资料采集工作台”，分为三个连续步骤，但任一时刻只突出一个主任务：

1. 创建门店：输入项目名称并创建真实后端项目；
2. 上传素材：至少上传菜单和门头，支持标记素材角色、优先级和主视觉；
3. 确认信息：默认通过对话补齐，用户明确选择后才调用 AI 识别并产生费用。

步骤导航允许查看已完成步骤；尚不具备前置条件的步骤必须说明缺少什么，不能只是灰掉。

### 3.3 后续页面

- `/projects/[projectId]`：项目工作台与刷新恢复入口；
- `/projects/[projectId]/facts`：事实卡与证据确认；
- `/projects/[projectId]/plan`：五图方案与 Prompt 审核；
- `/projects/[projectId]/generate`：异步生成、局部返工与版本；
- `/projects/[projectId]/deliverables`：视觉包预览、校验、导出与发布；
- `/assets`：素材库；
- `/settings`：公开配置和账号设置，不放模型密钥。

路由只在对应后端能力进入阶段范围后实现，不预先制作空壳冒充完成。

## 4. 视觉设计系统

### 4.1 视觉方向

当前确认参考为小云雀式 AI 工作台：安静的浅灰背景、白色高圆角任务卡、黑色主操作、克制的紫色状态点、宽松留白和清晰侧栏。借鉴信息架构、布局节奏和交互模式，不复制其品牌标识、文案、图片或受保护资产。

数值可在代表页评审后微调，但页面不得自行创造另一套颜色和圆角。

### 4.3 字体与密度

- 中文：`PingFang SC`, `Microsoft YaHei`, `Noto Sans CJK SC`, sans-serif；
- 英文和数字：Inter 可作为首选，但不得打包无授权商业字体；
- 正文 14–16px，辅助文字不低于 12px；
- 主标题桌面 32–40px，移动端 26–32px；
- 采用 4/8px 间距节奏；
- 输入、按钮和移动端触控目标最低 44px。

### 4.4 组件状态

所有按钮、输入、上传区、导航项必须实现：默认、hover、focus-visible、disabled、loading、error。错误信息使用文字说明，不仅依赖红色；仅图标按钮必须包含 `aria-label`。

## 6. 数据、API 与错误边界

### 6.1 API 原则

- 页面组件禁止直接拼接 `${API}/...`；
- 请求统一处理 JSON、超时、错误码、用户文案和请求 ID；
- 外部返回先以 `unknown` 接收，再在适配层收窄；
- 任务、事实、素材以服务端返回为准；
- 高成本 AI 操作必须二次确认、防重复提交并保留任务 ID；
- API Key、模型密钥、私密 Prompt 禁止进入 `NEXT_PUBLIC_*` 或浏览器包。

### 6.2 当前接口映射

| 用户动作 | 接口 | 前端结果 |
| --- | --- | --- |
| 创建门店项目 | `POST /api/v1/projects` | 保存 `project_id`，进入素材步骤 |
| 获取项目 | `GET /api/v1/projects/{id}` | 后续用于 URL 恢复 |
| 上传素材 | `POST /api/v1/projects/{id}/assets` | 展示真实素材清单 |
| 获取素材 | `GET /api/v1/projects/{id}/assets` | 刷新角色、优先级和文件名 |
| 开始整理 | `POST /api/v1/projects/{id}/analysis-runs` | 返回 `task_id`；区分零 Token 与 AI 模式 |
| 获取任务 | `GET /api/v1/tasks/{task_id}` | 后续映射任务状态并停止重复轮询 |
| 获取缺口 | `GET /api/v1/projects/{id}/coverage` | 展示最多 3 个问题与事实 |
| 提交补充 | `POST /api/v1/projects/{id}/clarifications` | 保留输入，刷新覆盖状态 |
| 选择目标门店 | `POST /api/v1/projects/{id}/fact-versions` | 新建事实版本并重新校验 |
| 锁定事实 | `POST /api/v1/projects/{id}/fact-versions/{version}/confirm` | 进入下一阶段资格 |

### 6.3 统一前端错误

```ts
type AppError = {
  code: string;
  userMessage: string;
  retryable: boolean;
  requestId?: string;
  fieldErrors?: Record<string, string>;
};
```

界面只展示可理解的 `userMessage`；原始堆栈、供应商响应、密钥和图片 Base64 不进入 UI 或埋点。

## 7. 状态模型

### 7.1 统一状态

| 前端状态 | 当前业务含义 | 用户可执行动作 |
| --- | --- | --- |
| `idle` | 尚未创建或未开始 | 填写并开始 |
| `submitting` | 正在创建、上传或提交 | 等待；禁止重复点击 |
| `running` | 后端正在整理或识别 | 查看阶段与费用模式 |
| `waiting_user` | 缺少事实或存在多门店 | 回答问题、选择门店或补图 |
| `succeeded` | 当前步骤完成 | 进入下一步 |
| `failed` | 请求或任务失败 | 保留输入并按错误类型重试 |
| `disconnected` | 浏览器与任务失联 | 通过项目/任务 ID 查询真实状态 |
| `stale` | 页面数据可能过期 | 主动刷新后端状态 |

### 7.2 页面状态矩阵

| 模块 | 初始 | 加载 | 空 | 等待用户 | 成功 | 失败 | 恢复 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 创建门店 | 可填写 | 按钮显示提交中 | 不适用 | 不适用 | 显示项目并进入上传 | 保留门店名 | 通过项目 ID 拉取 |
| 素材上传 | 说明必需项 | 单文件上传中 | 明确暂无素材 | 缺菜单/门头时说明 | 展示素材卡 | 保留已上传素材，可重传 | 重新 GET 素材 |
| 信息整理 | 未满足条件 | running 提示 | 不显示“无结果” | 最多 3 个问题 | 展示事实摘要 | 说明可否重试/是否扣费 | task_id + coverage 查询 |
| 事实确认 | 无 coverage | 拉取中 | 明确未开始 | 问答/候选门店 | 可锁定事实 | 保留已填答案 | 拉取最新事实版本 |

## 8. 对话优先与 Token 控制

- 默认“开始整理”使用 `use_ai: false`，只根据已知信息向用户追问，不产生模型调用；
- “AI辅助识别”是次级、显式、高成本操作，点击前说明用途和费用并要求确认；
- 同一次操作禁止并行调用千问和豆包；后续生图默认千问，失败后的下一次重试才允许切换豆包；
- 每轮最多显示 3 个真正阻塞的问题；
- 店名、价格、Logo、品牌和已设计素材属于强事实，必须二次确认；
- 不确定内容显示“待确认”，不得由 UI 文案包装成事实。

## 9. 上传与事实确认交互

- 上传前说明 PNG/JPEG/WebP、数量和大小限制；前后端都要校验真实类型；
- 菜单、门头为必需角色；招牌菜、菜品、环境、Logo、资质为可选；
- 已上传素材展示角色、优先级、主视觉和原文件名；
- 用户能够替换或删除素材的能力要等后端接口存在后再展示，不做无效按钮；
- 多门店图片必须展示候选名、区域、证据和置信度，并由用户选择；
- 菜单价格默认标记为需人工确认；
- 确认按钮写明结果“确认并锁定事实”，不使用含糊的“确定”。

## 10. 响应式与无障碍

最低真实验收宽度：390、768、1280、1440px。

- 390px：侧栏为抽屉或隐藏，步骤和主卡单列，底部操作不被键盘遮挡；
- 768px：侧栏可折叠，上传卡允许两列但不得压缩文字；
- 1280/1440px：主内容最大宽度约 1180–1320px，避免信息无限拉宽；
- 全流程无意横向滚动为零；
- 使用语义 HTML，Label 与输入关联，键盘可完成核心流程；
- `focus-visible` 清晰，状态提示使用适度 `aria-live`；
- 动画遵守 `prefers-reduced-motion`；
- 图片有替代文本，装饰 SVG 对辅助技术隐藏。

## 11. 安全、隐私与高成本操作

- 模型 Key 只保存在后端 `.env`，不得提交 Git；`.env.example` 只放变量名和安全示例；
- 用户素材不跨项目复用；数据保留期未冻结前，不声明永久保存或训练用途；
- 文件名、模型文本和 URL 均视为不可信数据；
- 不在日志和分析事件中记录完整菜单、图片、Prompt 或个人信息；
- AI 识别、未来生图、导出覆盖、发布与删除需明确影响并防重复；
- 政治敏感、色情、违法违规与提示词注入由前后端共同拦截，前端提示不替代后端安全判断。

## 12. 性能与可维护性

- 首屏不加载当前步骤无关的大型编辑器、图表或媒体库；
- 图片预留比例并使用合适尺寸，避免布局跳动；
- 二进制文件不长期存入 React State；
- 同一任务只允许一个轮询源，页面隐藏时降低频率；
- 成功、失败或取消后停止轮询；
- API 请求使用 AbortController 或等价方式处理页面卸载；
- 先测量再优化，不以动画掩盖真实等待。

## 13. 测试与交付门槛

### 13.1 自动检查

每个可交付阶段必须执行：

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

当前缺项处理：补齐 ESLint、Vitest + React Testing Library 和至少一条 Playwright 核心闭环后，以上命令才构成完整质量门槛；在此之前必须逐项注明“未配置”，不能写成通过。

后端相关改动同时执行：

```bash
cd backend && pytest
```

### 13.2 浏览器真实验收

- 使用真实后端，不以 Mock 画面宣布联调完成；
- 检查 Console、Network、重复请求和失败请求；
- 逐一检查加载、空、禁用、失败、等待用户、成功和刷新恢复；
- 检查 390/768/1280/1440px；
- 至少走通：创建门店 → 上传菜单/门头 → 零 Token 整理 → 补齐问题 → 锁定事实；
- AI 辅助模式单独记录模型、耗时、错误和是否真实扣费，不与零 Token 流程混淆。

### 13.3 不得宣布完成的情况

- 类型或构建失败；
- 核心按钮仍连接 Mock；
- 失败会清空用户输入；
- 重复点击能创建昂贵任务；
- 核心页面在手机不可用；
- Console 持续报错；
- 刷新后服务端任务无法找回且未明确列为已知问题；
- 实现明显偏离已确认的小云雀式代表页方向。

### 包含

## 16. 风险、降级与回退

- 风险：现有所有逻辑集中在 `page.tsx`，视觉重构可能误伤业务事件。处理：先保留 API 契约和函数行为，再逐步拆分并做真实闭环回归。

- 降级：AI 服务不可用时仍可走对话优先的零 Token 采集路径。
- 回退：每次代表页大改前保存独立版本备份；不得使用破坏性 Git 命令覆盖用户文件。
